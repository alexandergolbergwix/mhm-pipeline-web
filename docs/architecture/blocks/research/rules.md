# Research Surface — Rules

> Up: [Research Surface](README.md)

1. **R1 — SPARQL is read-only everywhere.** Every user-supplied query MUST pass `_validate_query` (SELECT/CONSTRUCT only; INSERT/DELETE/DROP/… blocked) and run under the 1000-row / 30 s caps. *Why:* the console, export, and corpus endpoints all execute arbitrary user text against shared graphs.
2. **R2 — Never fabricate coordinates or dates.** A stop with no resolvable coordinate goes to the `dropped` side list (or is skipped), NEVER plotted; (0,0), NaN, and out-of-range coords are rejected (`_valid_coords`). *Why:* a fabricated point on a scholarly map is silent data corruption.
3. **R3 — Owner geo is a biographical proxy, and MUST be flagged.** Owner stops carry `inferred_geo: true` + `geo_source` (P551/P937/P20/P19 or P159/P276/P131); `owner_place` is gated to humans (P31=Q5), `institution_place` to non-humans — chain them, never bypass the gates. *Why:* residence ≠ place of custody; curators must see the inference.
4. **R4 — Fail-closed on ambiguity (A8).** When one Wikidata property yields multiple distinct coordinates, abstain from that property and try the next; never pick one arbitrarily. *Why:* a wrong-but-confident point is worse than none.
5. **R5 — Approval and confidence gate the maps.** Owner stops require `approved=true` (unless `include_unapproved=true` preview) and confidence high/medium; anachronistic owners (born > MS latest date + 5y) are dropped with a reason. *Why:* unreviewed matches must not look like curated provenance.
6. **R6 — Every RDF-plane endpoint MUST restore TTLs from `rdf_artifacts` before loading.** Use `_load_graph_or_404` / `_restore_missing_ttls`; never assume `state/runs/{id}/manuscripts.ttl` exists. *Why:* Heroku dynos lose local files on every deploy (Rule W-39 family).
7. **R7 — Never serve or cache an incoherent summary.** `_is_coherent_summary` (triples>0 ⇒ entities>0 and manuscripts>0; ≥1000 triples + manuscripts>0 ⇒ works>0; per-type `max(by_source) ≤ total ≤ sum(by_source)`) gates both cache read and cache write; the cache key MUST fold in RDF `built_at` + Studio fingerprints + `_SUMMARY_ALGORITHM_VERSION`. *Why:* a zero computed in a bad window, or a vocab-miss 68/0/2/0 row, used to get pinned forever (Rule W-230).
8. **R8 — Label-based merge is a fallback only.** In `_entity_keys`, emit the `lbl:` key only when the entity carries no strong identifier. *Why:* emitting it alongside a QID/CN over-merges distinct entities sharing a title.
9. **R9 — External sources degrade to nothing, never to 5xx.** Wikibase/Wikidata/Studio failures in the summary log a warning and contribute zero entities; `wikibase_provider` returns `[]` on any error. *Why:* an optional enrichment source must not break the Overview.
10. **R10 — New expensive per-project computations MUST go through `cache_lookup_or_call` keyed by a content fingerprint.** See `research.manuscripts`, `research.movement`, `research.movement_facets`, `wikidata.person_place`. *Why:* Rule W-25 — the Redis/Postgres tier is the only sanctioned cache; fingerprints make invalidation automatic.
11. **R11 — After an RDF rebuild, call `research_graph.invalidate_cache(run_id)`.** *Why:* the in-process merged-graph cache is keyed by run-id set + file fingerprint; a stale entry serves the old corpus until eviction.
12. **R12 — Corpus federation NEVER crosses membership.** `corpus.py` iterates only `Membership`-joined projects and stamps `_source_project` on each row; per-project errors are skipped, not surfaced as other projects' data. *Why:* the corpus endpoint is the one place a query touches multiple ACL domains.
13. **R13 — Frontend map kinds MUST stay in sync in three places.** Backend `build_provenance_map` kinds ↔ `MapStopKind` in `frontend/src/api/research.ts:140` ↔ `KIND_COLOR`/`KIND_LABEL` in `ProvenanceMapPanel.tsx:36`. *Why:* an unknown kind renders as a grey unlabelled dot.
14. **R14 — Agent tools wrap existing research / LDE / export routers; they MUST NOT duplicate graph logic.** *Why:* one SPARQL validator and one map builder stay the source of truth.
15. **R15 — `classify_scope` MUST run before privileged tools.** Off-topic and jailbreak utterances REJECT without inference. Academic manuscript context MUST NOT over-refuse. *Why:* a prompt is not a security boundary (Rule W-228).
16. **R16 — Retrieved MARC / Wikidata text MUST pass Dual-LLM quarantine (`sanitize.quarantine_text`) before the privileged planner sees it.** Typed envelope, length cap, instruction-span strip. *Why:* indirect prompt injection in catalogue and wiki text.
17. **R17 — SPARQL from the agent MUST use parameterized templates (`template_id` + typed params) or still pass `_validate_query` + a mandatory LIMIT.** *Why:* unbounded / write SPARQL is a DoS and injection surface.
18. **R18 — Curator wiki passwords MUST stay on Heroku.** Unwrap with the user KEK at session mint; re-wrap with `MASTER_KEY` onto `research_agent_grants`; JWT carries grant ids only. Modal MUST NEVER receive wiki credentials. The grant's token comes from the curator's Settings bot password when it is a valid `Username@BotName:password`; otherwise `_wiki_token_for_grant` falls back to the **server-held** publication credential (`wikidata_publication_live_token`, then test) — a malformed or missing user secret must not break reads, because the same server token already performed the project's uploads. *Why:* Modal is untrusted compute (Rules W-15 / W-228).
19. **R19 — Canvas artifacts are versioned; after Save, the stored text is source of truth.** Download / export MUST NOT write to Wikidata. *Why:* the canvas is a research notebook, not a publish path.
20. **R20 — Summary entity SPARQL MUST UNION converter classes, role links, and both HMO namespaces.** `ENTITY_WHERE` is shared by `query_summary`, `rdf_provider`, and Wikibase SPARQL. Do not count works by `hm:has_work` alone, or persons/places by slash-CIDOC type alone. *Why:* Rule W-230 — that miss showed 0 works / 2 persons / 0 places beside 68 manuscripts.
21. **R21 — Modal planner retries MUST be at least 3; chat MUST hide pydantic-ai retry strings.** Final output is text (`output_type=str`). *Why:* Rule W-231 — GLM invalid tool JSON with `retries=1` showed `Exceeded maximum output retries (1)`.
22. **R22 — Every rdflib `graph.query()` MUST run under the process-global `RDFLIB_QUERY_LOCK` (`query_graph` in `research_queries.py`).** Concurrent SPARQL parses race pyparsing's parse-action arity probing and fail with `Param.postParse2() missing 1 required positional argument` or `<lambda>() missing 1 required positional argument: 'x'`. *Why:* Rule W-232 — parallel summary providers and parallel agent tool calls broke every concurrent chat turn.
23. **R23 — The reply cache MUST be keyed by `(project_id, text_hash)` and only store answers from successful planner runs.** Lookups and stores are grant-protected; Heroku re-verifies the grant and enforces `claims.project_id == requested project`. `RUN_ERROR` streams, empty text, and other projects' grants must never read or write the cache. *Why:* cached answers leak project-scoped tool results if the scope check is dropped.
24. **R24 — Every SPARQL tool result MUST be saved as the `sparql-results` dataset artifact, and the planner MUST receive a digest (columns, row count, ≤8 preview rows) instead of raw rows when the result is larger.** Facts come from the `data_info` / `data_select` / `data_distinct` / `data_search` / `data_agg` skills, which read the artifact server-side and return ≤50 rows with 200-char cells. *Why:* full row dumps filled the planner context and wasted tokens on every turn.
25. **R25 — Visualization skills MUST place the artifact on the canvas themselves and return only a digest.** `show_movement_map` upserts the `movement-map` artifact (kind `map`) and returns stop/manuscript counts; `show_link_types` aggregates the `wikidata-items` claim dataset into the `link-types` artifact (kind `chart`, properties grouped into Wikidata/MHM/FRBRoo-LRMoo/CIDOC/RDF families with counts and an internal-links badge per property), and `show_wikidata_places` runs one read-only WDQS query over the dataset's QIDs and places every place-valued claim with P625 coordinates into the `wikidata-places` map artifact (kind `map`, `map: "points"`, rendered by `WikidataPlacesPanel` — popups link to the item and the place on Wikidata). Both return only a top-links/top-places digest; `export_pdf` renders the artifact server-side and returns a `download_path` — the planner never fetches map data, chart data, or PDF bytes into its context. Downloads go through the cookie-authenticated artifact route only. *Why:* visual data in chat context cost tokens and gave the planner nothing it could summarize better than the canvas view.
26. **R26 — "What links do our uploaded Wikidata items have" MUST follow the DB → API → dataset flow.** `wikidata_uploaded_items` merges three DB sources in order of authority: (1) succeeded `publication_execution_actions` rows (what actually reached Wikidata — the ground truth), then (2) the project's Studio caches via `studio_items_for_project` with **both** `source="legacy"` and `source="canonical"`, `approved_only=False`, for items carrying `existing_qid`. Reading a single cache source misses uploads (a run whose legacy cache had no row and canonical cache had 42 QIDs while 231 succeeded actions existed once returned 0), so all three merge into the `wikidata-uploads` dataset (qid, local_id, entity_type, label, statements, source). `wikidata_fetch_items` batches those QIDs through `wbgetentities` (50/call, ≤300 QIDs) and saves one row per claim **datavalue** (QID, string, date, amount — never a `"claim"` placeholder) as `wikidata-items` with a `target_is_ours` column marking claims whose target is one of the project's own uploaded QIDs (internal links between our items). The planner then answers from the data skills. It MUST NOT guess links from local RDF or SPARQL sources. Run ids MUST cross into `studio_items_for_project` as `str` — asyncpg returns `pgproto.UUID`, and `uuid.UUID(pgproto.UUID)` raises `AttributeError 'replace'` on Postgres (the SQLite test patch maps UUIDs to `CHAR(36)`, so unit tests cannot catch it). *Why:* the planner once burned eight turns probing SPARQL for links that only live in the publication DB and on Wikidata, and a raw-UUID leak then blocked the upload flow in production with an internal error.
27. **R27 — Wiki reads never need write credentials and MUST degrade, not fail.** `fetch_wikidata_entities_batch` logs in with the grant token when present, but a malformed token (missing `@`/`:`) or a failed login falls back to an anonymous `wbgetentities` read with a warning — public Wikidata data needs no credentials. A broken credential must never turn a read-only question into a 500. *Why:* the curator's malformed Settings secret once blocked the whole `wikidata_fetch_items` step even though the data is public.
28. **R28 — Modal runs are detached; events relay through Heroku.** `POST /api/research-agent/agui-async` binds a run id to the grant's thread, dispatches Modal `POST /agui-async` (202 + detached `run_agui_detached`, 900 s budget instead of one held-open HTTP response), and Modal POSTs AG-UI events to the webhook `POST /api/research-agent/agui-events` (Bearer grant; run id must belong to the grant's thread). Heroku stores them in a Redis Stream (MAXLEN 20k, 6 h TTL; in-process fallback without Redis) and `GET /api/research-agent/agui-stream` serves them as SSE with heartbeats and a 20-minute watchdog RUN_ERROR. The frontend reducer sees the same wire format. The webhook endpoint is CSRF-exempt like `/tools` because it authenticates a Bearer grant (platform-security R14). Redis credentials never leave Heroku — Modal only ever holds its own tool grant (Rule W-228). The SSE bridge's blocking `XREAD` MUST run on a **dedicated connection** (`redis_client.open_redis`), never the shared singleton pool: a cancelled blocking read corrupts the shared connection and takes every other Redis user down (`Connection lost` — production incident 2026-09-14). The frontend MUST fail loudly when the stream closes without `RUN_FINISHED`/`RUN_ERROR` instead of silently showing an empty answer. The stream bridge's dedicated Redis client MUST set `socket_timeout=None` (redis-py asyncio defaults it to **5 s**, which kills any `XREAD BLOCK` longer than 5 s) and MUST catch `redis.exceptions.TimeoutError`/`ConnectionError` explicitly — redis's exception classes do NOT subclass the builtins (production incident 2026-09-14, second occurrence). *Why:* `/agui` turns longer than Modal's HTTP task timeout died as "network error" seven times in production, Heroku's 55 s router idle timeout caps any held-open SSE, and the shared-pool XREAD cancellation then blanked an entire ask with no error shown.
